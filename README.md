# PG Snapshots

Нативное приложение на Rust + Tauri 2 для снимков и полного восстановления баз PostgreSQL. Интерфейс открывается в собственном окне macOS или Windows; локальный HTTP-сервер и отдельный браузер не используются. Интерфейс и бэкенд работают без Node.js.

Макеты интерфейса, подготовленные перед реализацией, лежат в [`design/references`](design/references).

## Возможности

- несколько строк подключения PostgreSQL, у каждой своя история снимков;
- создание, удаление и полное восстановление снимка;
- автоматическое обновление статуса базы и размера;
- создание пустой базы: приложение сначала сохраняет текущую базу, затем заменяет её пустой базой с прежним именем, кодировкой и локалью;
- отображение и открытие локальной папки данных.

Перед восстановлением приложение загружает архив во временную базу и переключает имена баз только после успешной загрузки. На сервере PostgreSQL временно требуется место примерно под ещё одну копию базы. Пользователю нужны права на создание базы данных и завершение подключений к исходной базе. Роли и глобальные объекты PostgreSQL не входят в снимок одной базы.

Если архив содержит параметр `transaction_timeout`, а целевой сервер старее PostgreSQL 17, приложение повторит восстановление без этой неподдерживаемой команды, сохранив атомарность загрузки.

## Требования

- Rust stable и Cargo;
- клиентские PostgreSQL-утилиты `pg_dump`, `pg_restore` и `psql`;
- для macOS — Xcode Command Line Tools;
- для сборки Windows — Microsoft C++ Build Tools с компонентом «Разработка классических приложений на C++» и WebView2 Runtime.

В приложении без терминала путь Homebrew `libpq` распознаётся автоматически. На macOS установите клиентские утилиты, например `brew install libpq`. На Windows установите PostgreSQL client tools и добавьте папку `bin` в `PATH` либо установите PostgreSQL в стандартный каталог `Program Files\PostgreSQL`.

Если база работает в Docker, опубликуйте её порт на localhost, например `127.0.0.1:5432:5432`, и подключайтесь к `localhost:5432`. Само приложение не запускает и не останавливает контейнеры Docker.

## Запуск и сборка

Установите Tauri CLI один раз:

```sh
cargo install tauri-cli --version "^2.0.0" --locked
```

Запуск в режиме разработки:

```sh
cargo tauri dev
```

Сборка установочного пакета на текущей ОС:

```sh
cargo tauri build
```

На macOS сборка создаёт `.app` и `.dmg` в `target/release/bundle`. Перетащите `PG Snapshots.app` в «Программы», откройте приложение и выберите в Dock «Оставить в Dock».

На Windows сборка создаёт `.msi` и NSIS установщик `.exe` в `target/release/bundle`. Установщик проверяет наличие WebView2 на компьютере.

Нативные пакеты для обеих ОС также собираются workflow [`build-native.yml`](.github/workflows/build-native.yml): запустите его вручную на GitHub Actions или отправьте изменения в репозиторий. Windows пакет нужно собирать на Windows runner; проект не требует отдельной настройки фронтенда или Node.js.

## Данные и безопасность

Приложение использует системную папку данных пользователя. Полный путь показывается в интерфейсе в разделе «Папка данных». Внутри находятся:

- `connections.json` — подписи подключений и URI PostgreSQL;
- `backups/<id>/<timestamp>.dump` — снимки в PostgreSQL custom archive;
- JSON-файл с именем снимка и временем создания.

На Unix приложение ограничивает права каталога данных до `0700`, файла подключений и снимков — до `0600`. URI содержит пароль и хранится локально в открытом виде, но скрыт в интерфейсе и доступен текущей учётной записи ОС.

При первом запуске приложение переносит найденные `connections.json` и `backups` старой версии из папки проекта или рядом со старым исполняемым файлом в системную папку приложения. Исходные файлы не удаляются.
